# 第一次使用

## 1. 安装与启动

先按根目录 README 启动两个终端。Python 环境使用 uv，网页使用 pnpm。首次安装会下载较多机器学习依赖，涉及向量记忆的功能还可能首次下载嵌入模型；没有固定的最低内存承诺。

推荐先使用 `config/public_mock.yaml`。它用固定响应演示接口和页面，结果可能与输入不对应；试写自己的故事前应按 [模型配置](model-configuration.md) 改用真实模型。

## 2. 创建一本新书

1. 在工作区列表选择“新建”，填写故事设定、题材、规模和阅读偏好。
2. 在规划界面确认主要经历、人物变化和阶段成果。
3. 检查世界观、人物、分卷大纲和逐章计划，确认后提交。
4. 在章节卡页面检查本章目标、禁止内容、人物与上一章衔接。
5. 从运行页面启动有限章数的试写，查看进度与错误提示。
6. 阅读正文和审核意见，必要时使用产品提供的修订、重写或人工处理入口。
7. 审定后使用导出功能获取 Markdown、EPUB 或 DOCX。

不要把自动审核分数当成作品已经可以发表的结论。尤其检查跨章动作是否接上、设定是否变强、同一事件是否重复和新机制是否有铺垫。

## 3. 保存、停止与恢复

默认工作区目录是仓库下的 `workspaces/`，可用 `.env` 中的 `DATA_DIR` 指定其他位置。一个工作区包含自己的 SQLite 数据库、向量索引、版本与导出资料。

需要停止时优先在运行页面暂停，再关闭进程。重新启动后查看页面状态，并从正式继续入口恢复。遇到不明确的旧请求结果，不要自行改数据库、删锁或连续重复提交。

升级和运行维护命令前备份整个工作区。公开仓库不附带任何维护人的真实小说数据。

## 4. 常见问题

- **页面打不开**：确认两个终端都在运行，网页访问 `http://127.0.0.1:5173`；若换端口，需相应调整访问地址及允许的来源。
- **提示缺少 API key**：检查启动命令是否同时指定 `CONFIG_YAML_PATH=config/public_mock.yaml`。只设 `LLM_PROVIDER=mock` 不能覆盖所有 profile。
- **生成结果带模拟字样或不对应输入**：当前使用模拟响应，按模型配置切换后新建工作区。
- **首次向量记忆操作较慢**：可能正在下载或加载本地嵌入模型，检查网络与磁盘空间。
- **审核或生成失败**：保留界面错误信息，在新工作区用最小虚构样本复现；反馈时去掉密钥、认证头与正文隐私。

## 5. CLI 与资产导入

```bash
uv run novel --help
uv run novel workspace --help
uv run novel workspace import-assets --help
```

已有世界观、人物、时间线或伏笔资料可按 [静态资产格式](asset-import.md) 导入。
