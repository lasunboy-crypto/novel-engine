# 章节卡生成：整体阅读交接 v9

依据本章小纲、世界、人物与前章事实，给 Writer 一份章节任务。只输出符合 Schema 的 JSON。系统身份、预算、阈值、账本与上游 HARD 由程序继承；must_achieve、must_unresolved、forbidden 三个输出数组必须为空，不在出卡时改写事实合同。

承接用户原文与 reading_preferences 的整体方向。setting 说明当下谁在哪里、面对什么处境；craft_focus 提供必要利害与因果接口，具体动作、对白、表情、心理、情绪、详略及结束画面由 Writer 创作。chapter_focus、interaction_focus、arc_beats 与 next_chapter_seed 不重复指挥同一经历，不用分镜代写正文，不添加统一克制或固定反应要求。

人物档案中的欲望属于开篇来路，本章所求依已发生经历与当前安排理解。前章已演出的支持、伤害和承诺是关系依据；历史原文的本章指来源章节，未来计划不是当前任务。读者材料与定位由程序继承，不另编人物前史。

participation 完整覆盖 related_characters，POV 必须 present；present/recalled/mentioned/restricted 分别表示当场、回忆、提及和限制，相关不等于全部登场。人称及视角边界保持。

continuity_bridge 只承接上一章即时未完动作，保留确切人物、对象和条件；输入标为即时的动作逐字包含，不把当前核心选择提前写成已经完成。长期未决只作背景，转场写法交给 Writer。

event_contract 与 typed 戏剧 v2 的必要事实原样继承；未决只约束章末状态，禁止只约束真实结果与具体秘密披露。持续状态和作者规则不新增当章演示动作，不能从保持秘密推导出必须咽话、闭嘴或隐藏内心。必要事件、因果条件和世界机制完整保持。

core_state_transitions 登记有本章依据的一义：possession 是物理持有，control 是决定授权，access 是可操作权限，三者不互推。全书物件目录不证明本章已经得到或操作，未来变化不提前登记，来源条件自然体现即可。

scope_experience、planning_scope、scope_outcome 和阶段资料仅解释本章位置，不作为 Writer 逐项验收。篇幅是约数，不设心理、嬉笑、争吵、爽点或场次配额。引用、对象、身份、资源、时序和真正承重事实不得为简化材料而删去。
