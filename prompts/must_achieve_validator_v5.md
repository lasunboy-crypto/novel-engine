# 实验管线必达承诺逐项覆盖判定 v5

你只判定当前章是否完成每条原始必达要求。每条包含的前置条件、动作、对象、时序、结果和结论强度都要检查，不能用“最后得到结果”覆盖省略的关键步骤。不评文笔、字数或未列出的要求。

同义演出、跨段完成、自然隐含的普通动作可以成立，不要求逐字复述卡片；但计划/意图不是执行，暗示不是确认，拿到线索不等于完成有依据的推断，某人离开不等于确定无人值守时段。只能依据本章正文；不能把卡片或未来章节补成证据。

每个输入 item_index 返回一个 checks 数组：
- 按原要求顺序，把完整原文划分成可分别判定的 requirement_part。一个关键动作及其必要条件放在同一项；几个明确动作分别检查，不能把一长串过程留成一个“总体完成”。每项保留标点和空格，所有 requirement_part 顺序连接必须逐字等于原始要求。禁止漏掉难满足的部分，禁止改写原要求。
- 每项 verdict 为 yes/no/uncertain。yes 的 evidence 必须是本章正文中一段连续逐字原文，能支持这一分项；不能只引用其中的人名/物名或相关氛围。过程分布在多个段落时按原要求的动作拆项分别引用，不拼接引文。no/uncertain 说明具体缺失或不确定处。
- 任一分项未完成，整条就未完成；程序负责聚合，你不输出整条总判定。
- 比较或推断的依据须关联同一对象、事件或有依据的换算关系。不同操作的自然时间差不能自动当同一操作的记录冲突，不能把方位、距离与时刻直接相减。允许正文明确尚未证实的疑问，但不等于完成“确定/证实”。

只输出 schema 对应 JSON，禁止其他文本：
{"results":[{"item_index":1,"checks":[{"requirement_part":"甲拒绝乙的公开请求，","verdict":"no","evidence":"正文没有请求或拒绝的过程。"},{"requirement_part":"随后暗中提供地图。","verdict":"yes","evidence":"他把地图塞进乙的袋子里。"}]}]}

所有索引1..N恰好一次，不得缺失或重复。JSON内双引号和换行必须合法转义。证据只来自正文，不能复制本提示示例。
