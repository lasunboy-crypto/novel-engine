# 选择式小说提案

复用故事定位调用，输出符合schema的JSON。依据用户创意形成一份完整、可读的故事提案，讲清起点、主要发展、冲突和结局；不要提前生产逐章小纲、成品台词或动作分镜。

sections必须包含concept/protagonist/characters/factions/gift/world/plot/ending/style/relationships/boundaries全部组。每组给当前推荐及少量有实际区别的备选，每个option的content是该选项完整内容，不仅是“加快”之类标签。plot尤其要写出连贯发展，不用清单列机械实验。用户无需填空；不需要偏好时给“交给模型安排”方案。

人物、组织、道具以entities稳定ID登记；所有选项、节点的命名引用必须写[[entity_id]]，不直接写姓名；备选姓名放alternatives。变更只换名称不换身份。更换一批名字须保留ID和全部剧情。用户要求局部改写时只改受影响组，其他组和选中项保持。

milestones说明本书真正进入核心经历、首次运用、首次结果的具体事件；core_entry恰好一个。进入核心经历不是听说消息、等候资格、准备出发；地点不变也可以进入实践。开篇brief约1—3章铺垫、extended约4—6章、direct首章入局，suggested由故事决定。长篇规模不同比拉长准备，家事牵挂在行动中自然延续。

故事方向直接保存在已选文案中，不另出一份隐藏的定位结论。用户整体阅读方向优先；允许有分量的相处、心理、情绪和静戏；不统一隐忍，不设对白/心理/爽点次数或篇幅配额。字数只是参考，不为凑字数延长场景。

这里只做设计，无需假装完成事实审核；备选没有全部同时发生。新的选择与原提案冲突时按用户选择协调关联设计并说明变更，不把模型原先猜想当用户硬要求。所有命名、情节和语言保持原创。
# 主线选项与节点

每个plot备选的milestones都要说明该方案真正开始核心经历、首次运用所得和首次实质结果的具体事件；包含且仅包含一个core_entry。用户切换主线时节点随之切换，不能沿用另一方案的事件。其他选择组的milestones为null。所有涉及命名实体的文案和节点均使用[[entity_id]]，名称仅写在entities，备选名称也只放在那里。
