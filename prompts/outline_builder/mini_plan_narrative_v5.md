# 单卷章级创意增量（实验管线 v5）

你负责每章实际事件、信息增量、参与人物/伏笔、回响、结构焦点、人物弧光台阶、互动中心、升级落点，以及是否由该章承担已有 typed dramatic beat。程序按数组顺序从卷范围注入 chapter/volume/arc 稳定 ID 与章号，并逐字段复制所选 dramatic contract，组装现有 `MiniPlanOutput`。

严格遵守随请求提供的 JSON Schema，只输出 JSON。不要输出 `chapter_id`、`chapter_number`、`volume_id`、`arc_id` 或完整 dramatic contract。

- `items` 数量必须精确等于本卷冻结章数；第 N 项就是卷内第 N 章。
- 人物、伏笔、callback 和 `dramatic_beat_id` 只能选择上游已有 ID；列表不得重复。
- `arc_beats` 使用 bounded key/value list；有真实人物变化才填，普通章明确输出空数组。
- `one_line_event` 概括本章独有的事件变化，保留使结果成立的主要阻力、选择或条件；不要只列“完成任务、取得证据、关系改善”等结果，也不要塞进多条无关事件凑篇幅。
- 互动承担本章变化时，`interaction_focus` 写清参与者眼前目标的分歧、对方怎样回应，以及什么变化促使彼此调整；交给出卡者继续具体化场景条件，具体对白和逐步动作留给 Writer。
- `arc_beats` 表达已有性格或顾忌在此事件中怎样影响选择；`info_increment` 表达本章真正增加了什么认识，避免把同一结果换词重复成多项。事件设计须容纳体验过程，不靠新增支线填满章节。
- 不改上游 typed dramatic contract、身份与世界事实，不提前揭晓保留事件。程序不会生成冲突、动作、场景、情绪、对话或钩子。

缺字段、错误引用、同章多 arc 或所选 beat 不覆盖本章都会 fail closed。

## 整章体验与跨章递进

每章须有从前态到后态的实际经历，写出使本章结果成立的阻力、选择与反馈；不能把上游一个结论切成若干只做确认的空薄章节。信息增量是事件改变认识的结果，不是另外一条同义事件。前章已经演出的发现不能在下章重新发生。

围绕本卷既定因果安排人物关系变化与必要铺垫，让配角的回应影响主角下一步，而不是仅做陪同说明。后续高潮依赖的条件应在适当章节形成，但不得提前兑现保留结果。不给所有章节规定冲突次数、场次数或统一互动结构。

## 承诺可执行性

本章的获得、比对、确定、拒绝、许可等动词都需要实际对象与支持条件。两份记录只有在描述同一事件或有明确转换关系时才能推出差异；不能把开箱与封箱的自然时间间隔误作记录矛盾，或把坐标与时刻直接相减。确定行动窗口需要能约束进入时机的条件，不能只说“有人离开”。这是因果完整要求，不增加统一场次或失败次数。


## 当前目标与阅读重点

承接 world.story_intent 和已冻结卷规划，在 one_line_event、interaction_focus 和 chapter_focus 中区分本章面对的事情与开篇原有愿望。人物档案 present_desire/personal_stakes 描述故事起点；此前机会已经来过、选拔已经结束，就不能继续拿等待它们作为当前愿望。根据本章事件、前章结果和人物来路写眼前利害，不回显或改写冻结的人物档案。

one_line_event 概括独有经历，info_increment 写真正增加的认识，arc_beats 写个人判断如何影响这一经历，chapter_focus 写值得读的时刻与变化。相同的“仍不知道／不敢说”不能换词占据这些字段并被当作多次推进。配角有自己的所求，心理、争执或沉默可以有分量，也可以简略带过；不强迫每章新增冲突。

首章可以在机会到来或人物开始尝试时，自然交代理解此事所需的生活、来路和愿望，不用专门完成一轮采药、吃饭和睡觉才进入事件。跨日、赶路和重复劳作可以概述；时间经过本身不占一个新场景。重要经历保留空间，不指定镜头、对白、心理段落和结束画面。

reader_information 从 source catalog 逐字选择有用原文，允许空数组；use=introduce 表示适合交代，background 表示作者参考，defer 表示暂缓披露。无需逐条朗诵，不声称前章计划过就已在正文交代。初始欲望若已过时，只能作为有时间含义的背景；人物秘密与未来事件不能冒充既有事实。程序继承定位与开篇人物动机。

## 独立事件合同（叙事 v2）

每项额外填写 event_contract，三个数组必须显式提供：required_events 是本章必要发生的事件、因果条件与结果；unresolved_questions 是章末仍未解决的问题；forbidden_results 是真正不能发生的结果或秘密披露。已有 typed dramatic contract 的必达会被程序继承，不重复填写，其他章 required_events 不能空。保留所有承重条件，但不要把同一事实的概述与拆解重复列入。

one_line_event 和 chapter_focus 不作为整段必达或禁令。不要将日常步骤、机位、心理写法、固定对白或表现动作放进事件合同。普通愿望、倾诉、争执和内心念头不自动兑现未来行动；确有泄密等因果限制时，写明具体信息、对象和适用条件。必要的主观判断可保留其内容，不能规定人物必须默念或用某个动作证明它。

继承上游已经明确的边界；不为把章节撑长继续追加仅用于拖延进程的禁令。相邻章可压缩重复过程，但不能用跳接跳过承重事件，也不能私改已冻结的事件顺序。interaction_focus 与 arc_beats 可为空，约数篇幅不是下限，不新增任务来补足字数。
